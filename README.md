# WP-ChatGTP Site Audit API

Private REST API endpoints for WordPress auditing, structured inspection, and controlled site rework workflows.

Built because manually untangling old WordPress installs feels increasingly like excavating a cursed municipal archive with CSS glued to the walls.

---

## What this plugin actually is

This is **not** another “AI website builder”. i cannot stesss this enough.

It’s a controlled inspection layer for WordPress.

The goal is simple:

```text
Turn WordPress from:
    vague CMS soup

Into:
    structured queryable infrastructure
```

The plugin exposes internal site structure through private REST endpoints so external tooling, scripts, or automation systems can audit and eventually assist with rebuilding large or ageing sites.

Think:

* content inventory
* theme inspection
* structural audits
* automation pipelines
* migration prep
* AI-assisted analysis
* controlled editing workflows

Not:

* “click one button and destroy production”
* autogenerated Elementor nightmares
* 14 nested page builders committing crimes against semantics

---

# Current Features

## Site Summary Endpoint

```text
/wp-json/site-audit/v1/summary
```

Returns:

* site name
* site URL
* WordPress version
* active theme
* post count
* page count

Useful for quickly identifying:

* outdated installs
* environment mismatches
* staging/live confusion
* inherited horrors from 2017

---

## Page Inventory Endpoint

```text
/wp-json/site-audit/v1/pages
```

Returns structured page data including:

* ID
* title
* slug
* status
* modified date
* permalink
* template
* word count

This becomes surprisingly useful once sites exceed about 80 pages and everyone stops remembering what exists.

Which is every agency project eventually.

---

## Theme Inspection Endpoint

```text
/wp-json/site-audit/v1/theme
```

Returns:

* active theme
* version
* stylesheet
* template
* theme root

Useful for:

* rebuild planning
* child-theme verification
* deployment sanity checks
* discovering someone edited production directly at 2am three years ago

# Installation

## Manual Install

1. Download plugin ZIP
2. Upload via:

```text
Plugins → Add New → Upload Plugin
```

3. Activate plugin

Done.

WordPress will now expose the endpoints under:

```text
/wp-json/site-audit/v1/
```

# Why this exists

Modern WordPress development has a weird split:

| Problem                   | Existing Tools |
| ------------------------- | -------------- |
| Content management        | Fine           |
| Theme development         | Fine-ish       |
| Structural auditing       | Weirdly poor   |
| Rebuild intelligence      | Mostly absent  |
| Automation infrastructure | Fragmented     |

This plugin attempts to bridge that gap.

Especially for:

* inherited client sites
* bloated agency builds
* migration projects
* redesign prep
* accessibility reviews
* structured rebuild workflows

---

# Philosophy

This plugin intentionally avoids:

* arbitrary file editing
* theme overwrites
* executing remote code
* unsafe automation
* direct database mutation

Because “AI can edit production files live” sounds innovative right up until that moment it atomises the bloody sitexx `functions.php`.

I know i watched a junior dev do it.

# Development Notes

Namespace prefixing currently uses:

```php
tabarc_
```

to avoid collisions with the approximately 900 million plugins already existing in the ecosystem.

Future versions will likely move toward:

* class-based architecture
* route controllers
* modular audit services
* logging
* staged write operations

# Compatibility

Tested with:

---

# Security Notes

This plugin currently restricts access using:

```php
current_user_can('edit_pages')
```

Future versions should include:

* nonce validation
* role granularity
* endpoint-specific capability checks
* audit logging
* rate limiting

Because eventually somebody *will* point automation at production without reading documentation. I know they will, people and managers being them selves
